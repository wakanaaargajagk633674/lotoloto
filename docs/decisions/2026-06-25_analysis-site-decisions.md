# Analysis Site Decisions

Date: 2026-06-25 JST

## Decision 1: トップページは分析サイト中心にする

- 肯定意見: CSV、最新結果、統計分析を主役にすると信頼されやすい。
- 否定意見: 参考買い目を探しているユーザーには導線が弱くなる可能性がある。
- 斜め上の代替案: 週次分析サマリーをトップの中心にする。
- 最終判断: トップは分析サイト中心、参考買い目は控えめな導線として残す。
- 採用理由: ユーザー指示と、怪しい予想サイト感を避ける方針に合う。
- 不採用理由: 買い目を主役にすると誤認リスクが高まる。
- 次に検証すべきこと: トップから `/prediction` への導線が見つけやすいか。

## Decision 2: 公式データと履歴データを分けて扱う

- 肯定意見: みずほ銀行CSVは公式確認範囲として信頼性が高い。
- 否定意見: 公式CSVで全期間を取得できないため、過去全件の公式照合はできない。
- 斜め上の代替案: 公式確認範囲を可視化し、履歴ソース範囲を別表示する。
- 最終判断: 公式確認範囲とsougaku履歴範囲を分けて記録する。
- 採用理由: 正確性と透明性の両立ができる。
- 不採用理由: sougaku履歴を公式データとして扱わない。
- 次に検証すべきこと: 公式バックナンバーCSVの取得範囲拡張。

## Decision 3: 差分は隠さず品質レポートに出す

- 肯定意見: データ品質レポートは分析サイトとしての信用を高める。
- 否定意見: 差分が多く見えるとユーザーが不安になる可能性がある。
- 斜め上の代替案: 差分項目を「本数字」「金額」「口数」などに分解して表示する。
- 最終判断: `data/quality` にCSVとMarkdownを出力し、サイトでは methodology に掲載する。
- 採用理由: 透明性を優先する。
- 不採用理由: 差分をなかったことにしない。
- 次に検証すべきこと: 差分理由の項目別分類。

## Decision 4: パターン参考はsoft signalとして扱う

- 肯定意見: 数字帯、末尾、前回重複、連番などは分析コンテンツとして分かりやすい。
- 否定意見: 数字の除外や未来予測のように見えると疑似科学になる。
- 斜め上の代替案: 「法則探し」ではなく「偏りの見方」として説明する。
- 最終判断: パターン参考、候補バランス、低優先候補という表現に留める。
- 採用理由: ユーザー指示の用語方針に合う。
- 不採用理由: 参考サイト由来の表現をプロダクト主要語にしない。
- 次に検証すべきこと: UI文言から誤解が生じないか。

## Decision 5: CSVはBOM付きとBOMなしを両方出す

- 肯定意見: Excel利用者にも開発者にも使いやすい。
- 否定意見: ファイル数が倍になり、一覧が複雑になる。
- 斜め上の代替案: UIではBOM付きを主ボタン、BOMなしを補助リンクにする。
- 最終判断: BOM付きCSVを主ボタン、BOMなしCSVを補助リンクとして公開する。
- 採用理由: 初心者に優しく、再利用性も保てる。
- 不採用理由: BOMなしだけにはしない。
- 次に検証すべきこと: Excelでの文字化け確認。
