## 削除数字の定義

sougaku の削除数字ページは、削除数字を「出そうにない数字」「予想から外しても良い数字」と説明している。ページ上では、削除した集合に当せん本数字が含まれなかった場合、残った候補から選ぶ条件付き確率が上がるという倍率表が示されている。

本アプリではこの主張をそのまま採用しない。削除した数字に当せん数字が含まれないことを事前に知る方法は示されていないため、削除数字は「当たりやすさの根拠」ではなく、検証可能な仮説・スコアリング要素として扱う。

## 算出に使っていそうな指標

公開ページから削除数字の厳密な算出式は確認できなかった。推測できる材料は以下。

- 過去当選データ
- 出現回数
- 未出現期間
- 前回数字との関係
- ボーナス数字との関係
- 分散または候補絞り込み
- 「星の魔法陣」による分割・ばらけ

ただし、これは公開記述からの推測であり、公式な算式として扱わない。

## 分割方法・数字グループ

予想サービスページでは「星の魔法陣lite」が説明されている。

- ロト6: 6x6 の魔法陣を用い、43個から36個を選んで縦横斜めの14組を作る。削除数字選択タイプでは7つまで削除可能。
- ロト7: 7x7 の魔法陣を用い、37個をばらけさせて縦横斜めの16組を作る。

本アプリでは魔法陣そのものを再現しない。代替として、数字をレンジ、十の位、末尾、低中高、連番形成、チケット間重複で評価し、`sougakuPartitionScore` として「候補をばらけさせる」方向だけを取り込む。

## 確認した観点

| 観点 | 取り扱い |
|---|---|
| 出現回数 | total/recent/longTerm frequency として特徴量化 |
| 未出現期間 | lastSeenGap, averageGap, maxGap, z-score として特徴量化 |
| 前回数字 | appearedInPreviousDraw として説明用に使う |
| ボーナス数字 | appearedInPreviousBonus として参考特徴量にする |
| 連番 | 完全除外しない。ロト7では過度に避けない |
| 奇数偶数 | combo balance として使う |
| 低中高レンジ | combo balance として使う |
| 末尾 | diversity/sameLastDigit として使う |
| 十の位 | tensGroupDistribution として使う |
| 合計値 | 過去中心帯への距離として使う |
| パターン除外 | hard exclude ではなく soft penalty を既定にする |

## 更新頻度

ZIP のレスポンスでは Last-Modified が確認できた。

- loto6.zip: 2026-06-22 09:59:17 GMT
- loto7.zip: 2026-06-19 10:02:35 GMT

ロト6は月・木、ロト7は金の抽せん後に更新される前提で、Vercel cron では日次または抽せん翌朝に再取得する設計が妥当。

## ロト6とロト7で違う点

- ロト6は 1-43 から6個、ボーナス1個。
- ロト7は 1-37 から7個、ボーナス2個。
- ロト7は選択数が多く母集団が小さいため、連番や前回重複が構造的に起こりやすい。
- sougaku の絞り込み候補数はロト6が28個以内、ロト7が25個以内を目安としている。

## 取り込む価値がある考え方

- 削除数字を soft penalty として検証する。
- 削除数字の強弱をユーザー選択可能にする。
- 分割・ばらけを `sougakuPartitionScore` として抽象化する。
- 削除数字あり/なし、soft/hard、分割あり/なしをバックテスト比較する。

## 取り込むと危険な考え方

- 削除数字で当選確率が上がると断定する。
- 削除候補を既定で完全除外する。
- 魔法陣や削除数字を統計検証なしに真実として扱う。
- 「出にくい数字が存在する」と断定する。

## バックテストすべき仮説

- 完全ランダム vs 削除数字なしバランス型
- 削除数字 soft penalty
- 削除数字 hard exclude
- 分割方法のみ
- 削除数字 + 分割方法
- 期間分割、seed変更、直近窓変更に対する感度

初回実装では、sougaku 由来の厳密算式が不明なため、削除数字を `deletionCandidateScore` と `sougakuDeletionScore` に分け、分割を `sougakuPartitionScore` として近似した。
