## ループ1: 現状監査と論点設定

- **確率**: どの組み合わせも当せん確率は 1/6,096,454 (ロト6) で同じ。「予想の出し方」を改善できる余地は、当たりやすさではなく**当せんした場合の受取額**にしかない。
- **検定**: 第2140回までで出現回数の一様性を再検定 → χ² = 29.83 (自由度 42)、p = 0.920。ロト7は p = 0.815。「出やすい数字」は今回も検出されない。
- **懐疑**: 前回 (09-08) の再設計で入れた人気度回帰の R² = 0.30 は**学習データ内**の値。未来の回で本当に効くかは誰も確かめていない。
- **BT**: 賛成。今回の本題は「人気度モデルの標本外検証」にすべき。
- **購入者**: 当たりやすくならないなら何のための予想か、はっきり書いてほしい。
- **判断**: 頻度シグナルの扱いは変えない (λ = 0 のゲートが働いている)。人気度モデルの**標本外検証**と、検証結果に基づく**較正**を本会議の主題にする。

## ループ2: 人気度モデルは未来の回を説明できるか

- **ML**: 拡大窓のウォークフォワードで、各回の低位等級の口数 (log(当せん口数 / 推定口数×理論確率)) を、その回より前だけで学習した係数で予測する。
- **実測 (5等, 10回ごとに再学習)**: ロト6 標本外 R² = 0.27 (相関 0.52, 1,840回)。ロト7 標本外 R² = 0.02〜0.04 (相関 0.19, 545回)。
- **計量**: ロト6は「人気の数字が当せん番号に入った回は5等の口数が理論値より多い」という関係が、未来の回でも安定して再現されている。
- **懐疑**: ロト7は弱い。回数が約1/3で、ロト6ほどは信用できない。
- **判断**: ロト6の人気度モデルは実在の効果として採用を続ける。ロト7は「効果は弱い」と明記したうえで、理論値へ強めに縮小する方針にする。

## ループ3: 1等口数による直接検証と、等級換算の理論式

- **山分け**: 1等の口数は「その回の当せん組み合わせを買った人数」そのもので、Poisson(N·q) に従う。低位等級で学んだ人気が1等の口数を説明できれば、山分け見積もりの**直接の検証**になる。
- **確率**: 現行の等級換算 (mainCount / 一致数 = 2.0 倍) は、外れ枠に入る「当せん数字以外」の人気が当せん数字の人気の裏返しになる分を無視している。一次近似で正しく導くと、k 個一致の等級の感度は
  `c_k = k/m − (m−k)/(n−m)` (ロト6 5等: 0.419、つまり換算 2.39 倍。ロト7 5等: 0.471、2.12 倍) になる。
- **実測 (Poisson 回帰, 1等口数)**: 理論式で換算した予測の傾き s は、ロト6で **1.04 ± 0.08** (学習等級 2〜5)。理論値 1 とよく一致した。尤度比は約190 (p ≈ 10⁻⁴¹)。
- **検定**: 変更前の本番方式 (2.0 倍換算) では最適な傾きが 1.35 になり、人気差を約26%小さく見積もっていたことになる。
- **懐疑**: p 値が極端に小さいのは、1,840回・1等 2,955口という十分な観測があるから。効果量 (相対人気の幅) は後で確認すること。
- **判断**: 等級換算を理論式 c_k に置き換える。1等口数による Poisson 検証を、今後の標準の検証手順にする。

## ループ4: どの等級で学ぶか、Ridge をどれだけ効かせるか

- **ML**: 等級 {5}, {4,5}, {3,4,5}, {2,3,4,5} × Ridge {1, 4, 16, 64} の16通りを総当たりした。
- **実測 (ロト6)**: 5等の標本外 R² が最も高いのは 3+4+5 (0.288)。一方で**1等口数の尤度比が最も高いのは 5 (Ridge 4) と 4+5 (Ridge 16)** で、約197。2等・3等を入れると R² は上がるが1等の説明力は下がる (181〜185)。
- **数値**: 2等・3等は口数が数人〜数百人と少なく、一次近似の誤差 (Jensen 項) も大きい。1等の予測に混ぜると雑音になる。
- **BT**: 目的は1等の山分け見積もりなので、評価指標は1等口数の尤度を優先すべき。
- **ベイズ**: 同じ設定を両方のゲームで使えるなら、そのほうが過学習の余地が小さい。ロト7も 4+5 / Ridge 16 で傾き 0.965 と理論値に近い。
- **判断**: 両ゲームとも **学習等級 4+5、Ridge 16** を採用する (`popularityCalibrationSettings`)。

## ループ5: 並びのクセは数字の足し算を超えるか

- **行動**: 誕生日で選ぶ人は「全部31以下」の組をまとめて作る。数字ごとの人気の足し算では表せない**非線形の集中**があるはず。
- **実測 (1等口数, 回帰の上乗せ)**: ロト6「全部31以下」+0.23 ± 0.06 (約4σ)、「下1桁が3個以上そろう」−0.13 ± 0.07、5項目まとめた尤度比 20.1 (自由度5, p ≈ 0.001)。既存のヒューリスティック指数も上乗せで尤度比 17.7 だった。ロト7は5項目で尤度比 9.4 (p ≈ 0.09) で有意ではない。
- **懐疑**: 5つ試して1つ当たっただけかもしれない。
- **検定**: 「全部31以下」は多重比較 (ボンフェローニ5倍) を考えても p < 0.001。ただし係数の大きさは縮小して使うべき。
- **ゲーム**: 誕生日の選び方は購入者の構造的な行動で、すぐには変わらない。長期的に安定している理由がある。
- **判断**: 並びのクセを δ として Poisson 回帰に入れ、**事前分布 N(0, 0.1²) で縮小**する。ヒューリスティック指数との 50:50 合成は、較正モデルが使えるときはやめる (並びのクセは δ で代替)。

## ループ6: 較正そのものの標本外検証 (入れ子)

- **再現**: 傾き s や δ を全データで決めてから評価すると、評価に未来の情報が入る。較正も過去だけで決める**入れ子のウォークフォワード**が必要。
- **実測 (人気差なしモデルに対する標本外の対数尤度改善)**:

  | モデル | ロト6 (1,540回) | ロト7 (395回) |
  |---|---:|---:|
  | 変更前の本番方式 | +72.4 | +1.5 |
  | 理論換算 s=1 固定 | +73.8 | +2.4 |
  | 較正 s | +80.2 | +2.1 |
  | **較正 s + 並びのクセ δ (採用)** | **+81.0** | **+2.7** |

- **ベイズ**: 事前分布の幅 (s: 0.3 / 0.5、δ: 0.05 / 0.1 / 0.2) を振っても順位は変わらず、結果は頑健。
- **懐疑**: ロト6で +8.6 の改善は、1回あたり 0.006 nat。大きな改善ではない。
- **リスク**: 小さくても、これは1等の山分け人数という**実際に受取額を変える量**の改善で、偶然では出ない (1,540回で一貫している)。
- **判断**: 採用する。ロト7は改善が統計的に弱いことを報告書に明記する。

## ループ7: 1等だけでなく全等級の期待払戻で比べる

- **山分け**: ロト6の1口あたり期待払戻のうち、1等は約1/3〜1/2 で、2〜4等 (山分け) も合計で約1/3ある。1等だけで比べるのは片手落ち。
- **確率**: 自分が k 個一致したとき、当せん数字の人気の和の条件付き期待値は c_k·Σγ で、その等級の口数はさらに c_k 倍の感度で反応する。よって k 等の賞金は `exp(−c_k²·s·Σγ)` 倍になる (一次近似)。ロト6の5等は固定1,000円なので補正しない。
- **実測**: ロト6で、ランダムに選んだ口の払戻見込みを100とすると、1-2-3-4-5-6 は 71、3-7-8-11-12-22 は 62、13-24-32-36-40-43 は 124。
- **制度**: 当せん金の総額は当せん金付証票法で発売額の5割以下。どの組み合わせでも平均すると購入額を下回る。
- **データ**: 1等の基準額は「1等が出た回の総額の中央値」で、キャリーオーバーのある回に偏るため、払戻率の**絶対値**は過大に出る (中央値で 55%)。
- **依存・法務**: 過大な絶対額を表示すると「得をする」と誤解される。円や % の絶対値は出さないこと。
- **判断**: 期待払戻は「ランダムに選んだ買い目 = 100」の**相対指数**だけを表示する。あわせて、法律で5割以下と決まっていることを説明文に必ず入れる。重なりにくさの指数 (expectedShareScore) は、ランダムな口の払戻率の5%点〜95%点で 0〜1 に目盛る。

## ループ8: 生成アルゴリズムへの反映

- **設計**: 変更点は人気度モデルの内側に閉じ、戦略テーマ・重み・UI の構造は変えない。
  - `buildPopularityModel` が較正モデル (`fitCalibratedPopularity`) を持つ。
  - `combinationPayoutExpectation` と `expectedShareScore` は較正モデルから計算する。
  - 数字単体の人気度指数 (特徴量) も、較正済みの γ から作る。
  - データが不足するとき (ロト6 300回以下、ロト7 150回以下) は従来の方式へ自動で戻る。
- **組合せ**: 複数口の3個組被覆と再利用ペナルティはそのまま。人気を避けた結果、全口が同じ高い数字に寄らないことを確認した (31以下を2個以上残すガードも維持)。
- **確率**: 全数字が候補に残る「当せん確率中立」のテストは、変更後も通過した。
- **性能**: 較正モデルの構築はロト6で約90ms。正規方程式を累積して更新するので、再学習のたびに行列を作り直さない。
- **判断**: 実装した。重みの変更はしない (ev_share の意味が「較正済みの山分け見積もり」に置き換わるだけ)。

## ループ9: 安全性・表現・利用者目線

- **依存**: 払戻見込みが高い口を「お得」と表現しないこと → 説明文は「変わるのは受取額の見込みだけで、当せん確率は変わりません」「どの買い目でも平均すると購入額を下回ります」の2文を必ずセットにした。
- **表現**: 「期待払戻 約○円」は使わない。「ランダムに選んだ買い目を100として約○」だけにする。
- **AX**: 数値は整数に丸めて表示する。
- **購入者**: 「32以上を多めに入れると、当たったときに山分けが少なそう」という理解で十分。それ以上の説明はレポートにまとめてほしい。
- **法務**: 当せん保証・的中率向上の表現が無いことを確認した。
- **懐疑**: 1-2-3-4-5-6 のような特定の並びに人が集中する効果は、数字の足し算モデルでは過小評価される (実際はもっと人気)。
- **判断**: 限界としてレポートに明記する。特定の有名な並びを個別に扱うのは、根拠データが無いため見送る。

## ループ10: 最終確認と採決

- **QA**: 新規テスト7件 (公式の等級別確率と一致、合成データで理論傾き s≈1 を再現、入れ子検証で帰無モデルに勝つ、履歴不足で null、人気の低い組ほど払戻見込みが高い)。既存36件と合わせて43件が通過。
- **BT**: ウォークフォワードのバックテストを再実行した。当せん確率に関わる指標 (平均一致数・3個以上一致率) は、戦略間でもランダムとの間でも偶然の範囲のまま。これは想定どおりで、当たりやすさは変わっていない。
- **再現**: `npm run validate:popularity` で、表の数値をすべて再生成できる。
- **撤回条件**: 次の場合は較正を外し、理論換算 (s=1 固定) に戻す。
  1. 今後100回の入れ子検証で「較正 s + δ」が「理論換算 s=1」を下回る。
  2. 較正の傾き s が理論値 1 から ±3 標準誤差以上離れる。
  3. 1等口数の検証で、人気差なしモデルに対する改善が消える。
- **採決**: 可決 23 / 保留 2 (懐疑: 「改善量が小さい割に複雑になった」、購入者: 「画面での見え方を確認してから」)。反対 0。

## 採用しなかった案

| 案 | 理由 |
|---|---|
| よく出る数字・出ていない数字の重みを上げる | 一様性検定 p = 0.92 / 0.82。根拠なし |
| 2等・3等も人気の学習に使う | 5等の R² は上がるが、1等口数の説明力が下がった |
| 払戻の見込みを円や % の絶対値で表示する | 基準額がキャリーオーバーの回に偏り過大になる。「得をする」誤解を招く |
| ロト7でも並びのクセを強く使う | p ≈ 0.09 で有意でない。縮小して弱く残すだけにした |
| 1-2-3-4-5-6 などの有名な並びを個別に避ける | 購入実態のデータが無く、検証できない |
